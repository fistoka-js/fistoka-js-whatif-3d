# SPEC: the kit's contracts

This file is the contract between the parts. If code and this file disagree, fix one of them in the same change.
Audience: Sonnet/Opus maintaining the kit. Keep it short and exact.

## 1. The idea in five lines

- A video is described by one data file, `shows/<slug>/show.json` (a "show").
- A show is a list of **shots**. Each shot is a small stage: one **environment**, some **props**, one **camera** instruction, and **actions** that happen when words are spoken.
- Props, actions, environments and camera moves come from a fixed **catalogue**. A new topic should need only a new show file. A new *thing* (say, a submarine) needs one new prop file and nothing else.
- The browser page `kit/index.html` plays any show. `window.__renderAt(t)` draws the frame for time `t` (seconds). **Every frame is a pure function of `t`**: no state carried between frames, no `Math.random()` (use the seeded `rng`), no clocks.
- The catalogue is defined once, in code (`meta` objects). The checker, the docs and the LLM prompt are all generated from it.

## 2. Folders

```
kit/                 the browser player (ES modules, no build step)
  index.html         page: canvas + caption/label overlays
  vendor/            three.js (pinned copy) and the few addons used (see vendor/README.md)
  engine/            player.js show.js anchors.js state.js stage.js camera.js captions.js overlay.js
                     tween.js rng.js types.js materials.js registry.js places.js palette.js sounds.js
  props/             one file per prop, plus index.js that lists them; props/lib/ shared prop code (noise, surfaces)
  envs/              one file per environment, plus index.js; envs/lib/parts.js shared env parts
  actions/           actions.js (all generic actions)
  catalog.json       generated by tools/catalog.mjs (for the LLM prompt)
tools/               Node scripts (ESM): serve.mjs validate.mjs still.mjs timeline.mjs catalog.mjs
                     render.mjs gallery.mjs qa.mjs (to be built on tools/lib/)
  lib/               browser.mjs (Chrome + server + open a show + grab a frame), showfiles.mjs (read a show folder)
pipeline/            Python: voice, script, storyboard (LLM), mix, sfx, upload, run
shows/<slug>/        show.json voice.mp3 words.json script.txt (+ out/ for renders, git-ignored)
tests/               node --test files (tests/*.test.mjs) and pytest files (tests/py/)
docs/                SPEC.md (this), AUTHORING.md, HOW-IT-WORKS.md, CATALOG.md (generated), ASKING-CLAUDE.md
```

The page is always opened over `http://127.0.0.1:<port>/` from `tools/serve.mjs` (a tiny static server rooted at the repo), never from `file://`. URL: `kit/index.html?show=shows/<slug>`. The page fetches `show.json`, `words.json` and the audio relative to that folder.

Imports of three.js use the bare name `three` (and `three/addons/...`). The page has an import map pointing at `kit/vendor/`; Node resolves the same names from `node_modules` (same pinned version), so prop files can be imported in Node for checking and tests.

## 3. The show file

```jsonc
{
  "format": 1,
  "title": "What if the Moon disappeared?",
  "voice": { "audio": "voice.mp3", "words": "words.json" },
  "style": { "accent": "#ffe14d" },            // optional; see §8
  "shots": [
    {
      "id": "calm-earth",                      // unique, a-z 0-9 and dashes
      "start": "What if",                      // anchor (§4). First shot may omit it (= 0 s).
      "env": { "type": "space" },              // or just "space"
      "props": [
        { "id": "earth", "type": "planet", "look": "earth", "at": "center", "size": 1.2 },
        { "id": "moon",  "type": "planet", "look": "moon",  "at": [0.9, 0.3, -0.2], "size": 0.35 }
      ],
      "camera": { "move": "orbit", "focus": ["earth", "moon"], "framing": "medium", "angle": "front", "amount": 0.5 },
      "transition": "cut",                     // "cut" (default) or "dip" (quick dip through the env colour)
      "actions": [
        { "at": "vanished", "do": "disappear", "prop": "moon", "style": "pop" },
        { "at": "tides", "do": "label", "prop": "earth", "text": "TIDES SHRINK" }
      ]
    }
  ]
}
```

Rules:
- A shot lasts from its `start` to the next shot's `start`; the last shot runs to the end of the **last spoken word** (words.json) plus `tail` (default 0.4 s; optional top-level number `"tail"`, 0..3). That is the show's duration (Node cannot read the mp3's length, and the page and tools must agree). So shots can never overlap or leave gaps. The first shot always starts at 0 s.
- Shot `start` times must increase. A shot should last 1.5 s to 12 s (shorter or longer is an error; over 9 s is a warning).
- `words.json` is `[{"text": "What", "start": 0.10, "end": 0.31}, ...]` (seconds), in spoken order.
- Unknown fields are errors everywhere (catches typos), with a "did you mean" hint.

## 4. Anchors (when things happen)

An anchor is one of:
- `"some spoken phrase"`: the start time of the first word of the first place that phrase is spoken **at or after the start of the shot it is in** (for a shot's own `start`: at or after the previous shot's start). Matching ignores case and punctuation; 1 to 6 words.
- `{ "phrase": "some phrase", "edge": "start" | "end", "offset": -0.2 }`: same, with the end of the phrase and/or a shift in seconds.
- `{ "time": 12.3 }`: absolute seconds (avoid; breaks when the voice changes).
- `{ "shot": 0.5 }`: a fraction of the way through the current shot (0 = its start, 1 = its end). Only inside a shot.

An action's time must fall inside its shot. Error messages for a phrase that is not found must list the words actually spoken in that shot, with times (and say when the phrase is spoken, if it is spoken before or after the shot). `until` anchors are searched the same way as `at`.

## 5. Stage space, placement and size

- Each shot has its own stage centred on the origin. +x right, +y up, +z toward the viewer. One unit is roughly half the frame width at "medium" framing.
- `at` is a slot name or `[x, y, z]`. Slots: `center` [0,0,0], `left` [-0.8,0,0], `right` [0.8,0,0], `top` [0,0.9,0], `bottom` [0,-0.9,0], `top-left`, `top-right`, `bottom-left`, `bottom-right`, `front` [0,0,0.8], `back` [0,0,-1.2], `far-left` [-1.6,0,0], `far-right` [1.6,0,0]. In environments with a ground, y = 0 is where things rest on the ground unless the prop's meta says `floats: true`.
- Every prop is built to fit inside a unit box (largest side = 1); `size` (default 1) scales it. The engine measures the built object (skipping parts marked `noBounds`: glows, halos, air shells) and centres and scales it, so a prop file cannot get this wrong. A prop whose parts move (particles) returns its own `bounds` box instead.
- On a ground, a prop that does not float stands with its base at `at`'s y (the engine lifts it by half its height) and gets a soft blob shadow, offset away from the key light.
- Optional per-prop: `rotate: [xDeg, yDeg, zDeg]`, `hidden: true`. A prop whose first presence action is `appear` starts hidden automatically. Animatable params may also be given on the prop as starting values (e.g. `"progress": 0`).
- **Stage-space props** (meta `stageSpace: true`, e.g. `arrow`, `beam`) are drawn between their own points: params of type `point` (a slot, `[x,y,z]` or a prop id in the shot). They have no `at`/`size`/`rotate`, are not normalised, and cannot `move`, `scale`, `spin`, `orbit`, `bob`, `shake` or `pulse` (actions marked `placedOnly`). A point that names a prop follows that prop and stops at its surface.

## 6. Camera

`camera` fields (all optional):
- `focus`: prop ids to frame (default: all props in the shot). The engine frames the extent of their positions and sizes **over the whole shot** (sampled; so things that move or appear later stay in frame; short effects like pop overshoot, pulse, shake and arrive/leave flights are ignored), measured along the shot angle's screen axes, inside the safe rectangle: the frame minus the caption zone (bottom 24%) and a top margin (7%), minus 6% side margins. A vertical lens shift centres the safe rectangle (no tilting). Framing fills about 80% (medium), 102% (close) and 51% (wide) of the safe width (the frame minus side margins), i.e. a lone prop spans roughly 70% / 90% / 45% of the frame width; tall subjects are limited by the safe height instead. The subject's centre sits at 43% of the frame height. When the shot has no `focus` list, free-standing beams and arrows (given as coordinates) pull the frame outward by at most 12% of the subject's size per side (min one unit), so a long ray never shrinks the real subject; its far end may run out of the frame. Name a beam or arrow in `focus` (or a `focus` action) to frame it in full.
- On a ground the camera never goes below the surface.
- `framing`: `close` | `medium` (default) | `wide`.
- `angle`: `front` (default) | `high` | `low` | `top` | `side` | `three-quarter`.
- `move`: `drift` (default; the camera trucks sideways and turns a little, so the subject slides about 6% of the frame width over a shot at amount 0.5 and the background moves more; `amount` scales it) | `push_in` | `pull_out` | `orbit` | `rise` | `pan` | `still` (the only almost-static one: a tiny breathing motion; every other move visibly moves at its default amount).
- `amount`: 0 to 1 strength of the move (default 0.5).
- Actions can re-aim the camera mid-shot: `{ "do": "focus", "props": ["moon"], "framing": "close", "over": 1.2 }` and shake it: `{ "do": "shake", "strength": 0.5, "for": 0.6 }`.

Field of view is fixed (about 40° vertical) unless a move changes it.

## 7. Actions

Common fields: `at` (anchor, required), `do` (required), `prop` (most actions), `over` (seconds; each action has a default).
The value of every animated property at time `t` is computed by folding the prop's actions in time order (each tween starts from the value the previous one ends at). Continuous motions (`spin`, `orbit`, `bob`) are functions of `t - start`.

| do | what | key fields (defaults) |
|---|---|---|
| `appear` | show a prop | `style`: pop \| fade \| grow \| drop \| fly_in (pop); `from` slot for fly_in |
| `disappear` | hide a prop | `style`: fade \| shrink \| pop \| fly_out (fade); `to` slot for fly_out |
| `move` | move a prop | `to` slot/coords or `toward` prop id (+ `amount` 0..1 of the way, 0.75); `ease` |
| `scale` | change size | `to` (multiplier of its starting size); `ease` |
| `color` | tint the prop's main colour | `to` colour |
| `spin` | start/stop turning | `speed` turns per second (0.1), `axis` y |
| `orbit` | circle another prop (until a later move) | `around` prop id, `radius` (default: where it is now), `period` s, `tilt` deg |
| `bob` | gentle float up/down | `height`, `period` |
| `shake` | shake a prop or (no `prop`) the camera | `strength`, `for` |
| `pulse` | one quick swell and back | `strength` |
| `glow` | change emissive glow | `to` 0..2 |
| `set` | animate a prop-specific number | `param`, `to`, `ease` (the prop's meta lists `animatable` params) |
| `label` | callout text attached to a prop | `text`, `side` auto\|left\|right\|top, `until` anchor (default: shot end) |
| `text` | free on-screen text | `text`, `style` title\|stamp\|number, `pos` top\|middle, `until` |
| `count` | animated number | `from`, `to`, `unit`, `decimals`, `pos`, `until` |
| `icon` | pop an icon on a prop or place | `name` x\|check\|question\|warning\|heart\|bolt, `prop` or `place` (slot/[x,y,z]; not `at`, which is the time), `until` |
| `focus` | re-aim camera | `props`, `framing` |
| `sfx` | force or silence a sound | `name` (a file in assets/sfx) or `"none"` |

`over` is allowed only on actions that have a duration (not `spin`, `orbit`, `bob`, `shake`, `sfx`). The exact fields, types and defaults are in the `meta` of `kit/actions/actions.js` and in the generated docs/CATALOG.md.

Labels, text, counters and icons are HTML overlays positioned from 3D points each frame (crisp text, and the QA tool can read their boxes). They stay inside the safe rectangle (never in the caption zone); long text shrinks to fit. Labels avoid collisions (`chooseLabelPlacement` in `engine/overlay.js`): each label picks its side once, from the picture a moment (0.25 s) after it starts, and keeps it for its whole life. It tries the `side` asked for (auto: beside the prop, on the side with room), then the other sides, then slides along the side and moves further away; it must not cover its prop, other labels, texts, counters or icons that are on screen at the same time, and must stay inside the safe rectangle. While a `title` text is on screen the top band (7.5% to 19% of the height) is closed to labels. A long label wraps to at most two lines (half the frame width) and shrinks to as little as 70% of its size rather than overflow. Captions are also HTML.

Sound effects are derived by `tools/timeline.mjs` into `shows/<slug>/out/timeline.json` = `{"duration", "shots": [{id, start, end}], "events": [{t, sfx, why}]}`; the page itself plays no effects. The mapping is one table, `SOUND_RULES` in `kit/engine/sounds.js`: shot change → whoosh (not at 0 s), appear → pop, disappear → none, icon x → buzz, icon check → chime (other icons → pop), shake → rumble, count → tick at its start, label/text → tick, glow that brightens → shimmer. An `sfx` action removes every automatic sound within 0.25 s of its time and (unless `"none"`) adds its own.

## 8. Look (what makes it read as 3D, applied by default)

Every environment provides: a key light, a fill, a rim light, a background with a gradient or depth layers, distance haze, slow "motes" or stars at several depths for parallax, and a grounding cue (soft blob shadow under props when there is a ground). `space` has an optional `tint` (a colour) for its nebula wash; `studio` has a soft horizon glow, a gentle vignette (a dark-edged quad held in front of the camera) and dust at three depths; `sky` grass has patches, mown stripes and far hills. A `beam` is drawn as light: crossed ribbons (thin bright core plus a soft wide glow, tapered at both ends) with a gentle pulse travelling along it as a function of t, and flares at its head and source. The camera never sits fully still. Props use `engine/materials.js` helpers so shading, saturation and outline/rim treatment stay consistent across videos (the channel's visual identity). Captions: 4 words max per chunk, white with the active word in the accent colour, heavy stroke (ported from the approved chameleon video).

## 9. Module interfaces

### Prop: `kit/props/<name>.js`
```js
import * as THREE from 'three';
export const meta = {
  name: 'planet',
  summary: 'A lit planet or moon. Looks: earth, moon, mars, ...',   // one line, shown to the LLM
  tags: ['space'],
  floats: true,                                                     // does not rest on the ground
  params: {                                                         // checked by engine/types.js
    look:  { type: 'enum', values: ['earth','moon','mars'], default: 'earth', doc: 'surface style' },
    color: { type: 'color', default: null, doc: 'override main colour' },
    rings: { type: 'bool', default: false, doc: 'Saturn-style rings' }
  },
  animatable: { atmosphere: { min: 0, max: 1, default: 0, doc: 'glow of the air shell' } },
  sounds: {}                                                        // optional sfx hints
};
export function build(params, ctx) {        // ctx: { THREE, rng (seeded per prop), mat (materials.js), quality, scale, color(name) -> 0xRRGGBB }
  const group = new THREE.Group();
  // ... build meshes into group (use ctx.mat.solid(...) for lit parts; mark glows with ctx.mat.noBounds) ...
  return {
    object: group,
    update(t, state) {},                    // optional; t = seconds since shot start; state = { visible, opacity, position, scale,
                                            //   rotation, color, glow, params: { <animatable>: value }, points: { <point param>: { at, radius } } }
    setColor(hex) {}, setGlow(v) {},        // optional; default: the materials marked "main" (ctx.mat.solid) are tinted / made emissive
    bounds,                                 // optional THREE.Box3 (object space): use instead of measuring (parts that move)
    dispose() {}
  };
}
```
Extra meta flags: `stageSpace: true` (see §5). `params.color` is the base colour that the `color` action tweens from (white if none: a texture tint).

### Environment: `kit/envs/<name>.js`
`meta` (name, summary, params, `ground: true | false | (params) => bool`) and `build(params, ctx)` (ctx: { THREE, mat, rng, scale (≈ the shot's subject radius), color }) → `{ object, lights, fog, background, update(t, cam) }`. `lights[0]` must be the key light (blob shadows fall away from it); there must be at least key, fill and rim directional lights. `background` is a 0xRRGGBB number (used by the "dip" transition). `cam` = { position, target, distance }; things meant to be infinitely far (dome, far stars) follow `cam.position`.

### Types (`engine/types.js`)
`number {min,max}`, `int`, `bool`, `color` (#rgb/#rrggbb or a palette name), `enum {values}`, `string {max}`, `place` (slot or [x,y,z]), `point` (slot, [x,y,z] or a prop id in the shot), `anchor`, `propId`, `list {of,min,max}`. One function `check(value, typeSpec, path, ctx)` → list of `{path, message, hint}`; `checkFields(obj, specs, path)` adds unknown-field ("did you mean") and required-field checks. Messages are written for a person: what was given, what is allowed, and the nearest valid name.

### Action entries (`kit/actions/actions.js`)
`{ doc, prop: 'required'|'optional'|'none', over, kind, fields, ... }` with kind `channel` (a value that tweens and stays: `value(a, t, from, ctx)`), `effect` (adds on top: `effect(a, t, ctx)`), `overlay`, `camera` or `sound`. Folding is in `engine/state.js`: a channel's value at t comes from the last action that has started, starting from the value the previous one had at that moment. Pure: the same t gives the same state whatever was asked before.

### Validator (`tools/validate.mjs`)
`node tools/validate.mjs shows/<slug>` checks the show against the catalogue and the words file without a browser. Prints every problem as `ERROR shots[2].actions[1].prop: "mooon" is not a prop in this shot (props here: earth, moon). Did you mean "moon"?`. Exit 0 = ok (warnings allowed), 1 = errors, 2 = bad command. `--json` prints machine-readable results for the repair loop.

### Other tools
- `serve.mjs`: static server on 127.0.0.1, `--port` (default: a free port, printed).
- `still.mjs <slug> --at 3.2,10 | --every 3 [--sheet] [--size WxH]`: PNG stills in `shows/<slug>/out/stills/`; `--sheet` makes one contact-sheet JPEG (2 tiles per shot by default, small tiles labelled with time and shot).
- `timeline.mjs shows/<slug>`: writes `shows/<slug>/out/timeline.json` (§7).
- `tools/lib/browser.mjs`: the one place that launches Chrome: `openSession()`, `session.openShow(slug, {width, height})` (waits for `__ready`, throws `__error`), `grabFrame(page, t, {type, quality})`, `checkFreeRam()`, `findChrome()`. Build render/gallery/QA on it.
- `render.mjs <slug> [--chunks N] [--size 1080x1920] [--fps 30]`: MP4 (video + voice) in `shows/<slug>/out/`.
- `gallery.mjs`: one still of every prop (and every env) into `docs/gallery/`, for eyeball review.
- `catalog.mjs`: writes `docs/CATALOG.md` and `kit/catalog.json` from the `meta` objects.
- `qa.mjs <slug>`: automatic picture checks (see docs/HOW-IT-WORKS.md).

All browser tools use puppeteer-core with the installed Chrome (`CHROME_PATH` env, else the usual Windows/Linux paths), software WebGL flags `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`, and wait for `window.__ready === true` before drawing.

## 10. Page hooks (for tools and tests)

- `window.__ready`: true once the show is built; `window.__error`: a message string if it failed (also shown on the page).
- `window.__renderAt(t)`: draw the frame for time `t`.
- `window.__info()`: `{ duration, fps, shots: [{id, start, end}] }`.
- `window.__boxes(t)`: draws `t`, then returns screen rectangles (pixels) of every visible prop, label, text, count, icon and the caption line: `[{ kind: 'prop'|'label'|'text'|'count'|'icon'|'caption', id, x, y, w, h }]`, for QA.
- Without `?render=1` the page shows a play button and plays with the audio (preview mode); `&t=12.5` shows that moment first.

## 11. Tests

`node --test "tests/*.test.mjs"` (Node 24 does not accept a bare folder: `node --test tests/` fails with "Cannot find module"). Only `tests/browser.test.mjs` opens Chrome; it skips itself when Chrome is missing or under 2 GB of memory is free.
